# Platform Overview

The RAG platform supports ingesting markdown, text, and small PDF files through a single API endpoint. Each document is split into overlapping chunks to keep context windows stable for retrieval. The offline profile uses deterministic feature-hash embeddings; an optional sentence-transformers model provides semantic vectors. Chunks are stored in Qdrant or pgvector for similarity search.

The API exposes a /query endpoint that builds independent dense and lexical candidate lists. Hybrid mode combines those rankings with weighted reciprocal-rank fusion (RRF), allowing an exact lexical match to recover a chunk that dense retrieval missed. The service returns citations with the document id, source, snippet, fused score, component scores, and dense and lexical ranks so clients can audit retrieval decisions. Responses are extractive evidence, not free-form LLM generation, and the service abstains when retrieval confidence is below its configured threshold. Operators can tune chunk sizes, candidate depth, RRF lexical weight, and the confidence threshold through environment variables without code changes.
